## 1. 背景与目标

本项目用于追踪基金博主的持仓和操作表现。第一版先建立基础数据能力，让用户可以维护博主、基金和博主在观察起始日的初始持仓。

第一版完成后，应能完成以下事情：

1. 录入并维护博主基础信息。
2. 录入并维护基金基础信息。
3. 为指定博主和指定基金录入观察起始日的初始持仓。
4. 查询博主、基金、初始持仓数据，为后续 OCR、净值、收益计算模块提供基础数据。

## 3. 使用场景

### 场景一：新增博主

使用者发现一个新的基金博主，需要在追踪池中记录：

1. 输入博主名称。
2. 输入所属板块。
3. 选择观察开始日。
4. 保存后，博主出现在博主列表中。

### 场景二：录入初始持仓

使用者已经确定某个博主在观察开始日的持仓：

1. 先确认博主已存在。
2. 先确认基金已存在。
3. 新增初始持仓，填写份额、成本金额、记录日期。
4. 保存后，可以在初始持仓列表中查看该数据。

## 5. 功能需求

## 5.1 博主管理

### 新增博主

使用者可以新增一个博主。

必填字段：

- 博主名称
- 所属板块
- 观察开始日

业务规则：

1. 博主名称不能为空。
2. 博主名称建议全局唯一，避免重复追踪。
3. 观察开始日必须是合法日期。
4. 新增成功后，后端返回完整的博主基础信息。

### 查询博主列表

使用者可以查看博主列表。

列表字段：

- 博主 ID
- 博主名称
- 所属板块
- 观察开始日
- 观察天数
- 状态
- 创建时间
- 更新时间

业务规则：

1. 列表按创建时间倒序返回，或按使用者指定字段排序。
2. 支持按博主名称关键字搜索。
3. 支持按板块筛选。
4. 支持按状态筛选。
5. 观察天数和状态由后端根据观察开始日计算，不落库。

### 查询博主详情

使用者可以查看单个博主的基础信息。

详情字段与列表字段一致。

### 编辑博主

使用者可以修改博主名称、所属板块、观察开始日。

业务规则：

1. 编辑后，观察天数和状态应根据新的观察开始日重新计算。
2. 博主名称不能与其他博主重复。

### 删除博主

使用者可以删除博主。

业务规则：

1. 删除博主时，级联删除该博主名下的初始持仓。
2. 删除前，前端需要二次确认。
3. 后端接口收到删除请求后直接执行删除，不做二次确认；二次确认由前端负责。

---

## 5.2 基金管理

### 新增基金

使用者可以新增基金。

必填字段：

- 基金名称
- 基金代码

业务规则：

1. 基金名称不能为空。
2. 基金代码不能为空。
3. 基金代码建议全局唯一。

### 查询基金列表

使用者可以查看基金列表。

列表字段：

- 基金 ID
- 基金名称
- 基金代码
- 创建时间
- 更新时间

业务规则：

1. 支持按基金名称或基金代码搜索。
2. 第一版不做基金删除。

### 编辑基金

使用者可以修改基金名称和基金代码。

业务规则：

1. 编辑后，基金代码不能与其他基金重复。
2. 编辑基金不会自动修改历史初始持仓中的冗余显示字段，接口查询时应通过基金表关联获取最新名称和代码。

---

## 5.3 初始持仓

### 新增初始持仓

使用者可以为指定博主和指定基金录入观察起始日的初始持仓。

必填字段：

- 博主 ID
- 基金 ID
- 份额
- 成本金额
- 记录日期

业务规则：

1. 博主必须存在。
2. 基金必须存在。
3. 份额必须大于等于 0。
4. 成本金额必须大于等于 0。
5. 同一博主、同一基金、同一记录日期只允许存在一条初始持仓。

### 查询初始持仓列表

使用者可以查看初始持仓列表。

列表字段：

- 初始持仓 ID
- 博主 ID
- 博主名称
- 基金 ID
- 基金名称
- 基金代码
- 份额
- 成本金额
- 记录日期

业务规则：

1. 支持按博主筛选。
2. 支持按基金筛选。
3. 博主名称、基金名称、基金代码由后端关联查询返回，避免前端再自行拼装。

### 编辑初始持仓

使用者可以修改初始持仓。

允许修改字段：

- 博主 ID
- 基金 ID
- 份额
- 成本金额
- 记录日期

业务规则：

1. 修改后的博主和基金必须存在。
2. 修改后的份额和成本金额必须大于等于 0。
3. 修改后仍需满足同一博主、同一基金、同一记录日期唯一。

## 6. 数据字段定义

## 6.1 博主

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| blogger_id | int | 是 | 主键，后端生成 |
| name | string | 是 | 博主名称，全局唯一 |
| sector | string | 是 | 所属板块 |
| observe_start_date | date | 是 | 观察开始日，格式 `YYYY-MM-DD` |
| created_at | datetime | 否 | 创建时间，后端生成 |
| updated_at | datetime | 否 | 更新时间，后端生成 |

派生字段：

| 字段 | 说明 |
| --- | --- |
| observe_days | 当前日期减去观察开始日的天数 |
| status | `observing` 表示观察期中，`active` 表示已满 30 天 |

状态规则：

| 状态 | 条件 |
| --- | --- |
| observing | 观察天数小于 30 天 |
| active | 观察天数大于等于 30 天 |

---

## 6.2 基金

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| fund_id | int | 是 | 主键，后端生成 |
| name | string | 是 | 基金名称 |
| fund_code | string | 是 | 基金代码，全局唯一 |
| created_at | datetime | 否 | 创建时间，后端生成 |
| updated_at | datetime | 否 | 更新时间，后端生成 |

---

## 6.3 初始持仓

| 字段 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| initial_position_id | int | 是 | 主键，后端生成 |
| blogger_id | int | 是 | 关联博主 |
| fund_id | int | 是 | 关联基金 |
| shares | number | 是 | 持有份额，大于等于 0 |
| cost_amount | number | 是 | 成本金额，大于等于 0 |
| record_date | date | 是 | 记录日期，格式 `YYYY-MM-DD` |
| created_at | datetime | 否 | 创建时间，后端生成 |
| updated_at | datetime | 否 | 更新时间，后端生成 |

关联字段：

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| blogger_name | 博主表 | 后端关联返回 |
| fund_name | 基金表 | 后端关联返回 |
| fund_code | 基金表 | 后端关联返回 |

## 7. 流程说明

### 7.1 基础数据录入流程

```text
新增博主
    ↓
新增基金
    ↓
选择博主
    ↓
选择基金
    ↓
录入份额、成本金额、记录日期
    ↓
保存初始持仓
```

### 7.2 博主删除流程

```text
前端弹出二次确认
    ↓
使用者确认删除
    ↓
前端调用删除博主接口
    ↓
后端删除博主
    ↓
后端级联删除该博主的初始持仓
    ↓
前端刷新列表
```

## 8. 边界与异常

| 场景 | 处理方式 |
| --- | --- |
| 博主名称重复 | 返回业务冲突错误，前端提示“博主名称已存在” |
| 基金代码重复 | 返回业务冲突错误，前端提示“基金代码已存在” |
| 初始持仓重复 | 同一博主、同一基金、同一记录日期已存在时，返回业务冲突错误 |
| 博主不存在 | 初始持仓新增或编辑失败，返回资源不存在错误 |
| 基金不存在 | 初始持仓新增或编辑失败，返回资源不存在错误 |
| 份额为负数 | 返回参数校验错误 |
| 成本金额为负数 | 返回参数校验错误 |
| 日期格式错误 | 返回参数校验错误 |
| 空列表 | 前端显示空状态 |
| 并发新增重复数据 | 后端通过唯一索引兜底，返回业务冲突错误 |

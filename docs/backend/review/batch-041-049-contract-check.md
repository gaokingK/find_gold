## 三、数字核对明细

### 3.1 唯一一处对不上：负份额后再卖的成本（045 vs 契约 5.2 边界 2）

**两边各写的什么：**

- 契约 `api-contract-gaps.md` 5.2 节 4.1 边界 2：「卖出前累计份额为负时，仍按上述公式计算（分母为负，结果照实返回），不做任何修正。」
  按此公式推 045 的数据（博主 2 / 基金 103：期初 500 份 @10000，09-19 卖 800 份后份额 -300、成本 -6000；09-26 再卖 200 份）：
  平均单位成本 = -6000 / -300 = 20，本次卖出成本 = 200 × 20 = 4000，**最终成本 = -6000 - 4000 = -10000.00**，份额 -500。
- 任务 045（沿任务 030 已实现的 `else` 分支）：「卖出前没有正份额 → 成本保持不变，只继续减少份额」，**最终成本 = -6000.00**，份额 -500。045 的全部下游期望值都建在这个数上：收益接口 fund 103 cost -6000、market_value -10500、profit -4500。

**唯一正确值：cost_amount = -6000.00（不是 -10000）。**

**裁决理由：**
1. 份额 ≤ 0 时"平均单位成本"没有经济含义——一个已经不存在的持仓再除出一个 20 元/份，是纯算术假象，按公式走只会把无意义的数字继续放大；
2. 030 的实现已验收，045 的验证链（快照、09-30 收益、09-29 对照组三处）全部依赖 -6000，改它要动代码加 3 处期望值；
3. 046 的函数级用例只覆盖了"份额 = 0"分支（期望 cost 0，两种口径下结果相同），没有用例锁死负份额分支，所以改契约条款不需要改任何测试。

**要改的是契约条款（我报告 5.2 的边界 2），不是任务文档。** 替换文本见第四节第 3 条。

        )

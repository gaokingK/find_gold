## 一、结论先行

**1. 这 40 份文档的质量在线，但有两处"执行即死"的硬伤，必须先修再发。**
`028` 把 `create_fund` 当成 pytest fixture 传给测试函数，而 `conftest.py`（任务 015 产出）里根本没有这个 fixture；`032` 又重新本地定义了一遍 `create_blogger`/`create_fund`，直接违反任务 016、017 白纸黑字写的完成标准。三份文档给出了三种互斥的测试辅助函数写法，新手无论照哪一份做，都会和另一份打架。

**2. 最大的风险不是文档写得差，是"测试和交付保障在后面几天整体消失了"。**
001–022 每个接口都有配套测试任务；033–039 七个接口任务**一个测试都没有**，只要求"`pytest -q` 全部通过"——跑全量不等于有新测试。收益率 `null`、缺净值 `null`、成本为负、038 那个"缺净值博主排在前面就 500"的经典坑，全靠手工 curl 验一遍，改一次代码就失守一次。第 8、9 天是这套系统数字最密集的部分，零回归保护是不可接受的。

**3. `040` 要求验收一个根本没人实现的接口，第 9 天最后一步必然卡住。**
`040` 步骤 5 和验收清单都要求 `GET /api/v1/nav-history` 可用，但 001–040 里没有任何任务实现它。许清楚已在 `api-contract-gaps.md` 5.3 给出了接口定义草稿——**照那份补一个执行任务，编号 `026A`**（插在第 6 天 026 之后，可复用 023 的统一分页工具），不要动 040 的验收要求。

**4. 前后端联调的前置能力一个任务都没有。**
CORS、全局错误处理器（404/405/非法 JSON/500 统一 JSON）在 40 份任务文档里零出现，只躺在 backlog 里。前端跑在 `localhost:5173`，后端跑在 `127.0.0.1:5000`，没有 CORS 浏览器全拦；没有全局错误处理器，Flask 返回 HTML 错误页，前端 `response.json()` 直接崩。这两件事不做完，040 的"可以交付前端联调"就是空话。

**5. 除了上面 4 条，还必须做三件小事才能开盘：**
① `docs/backend/plans/README.md` 顶部"当前应执行任务"指针停在 004，新手接手第一件事就会做错任务；② 数据库字段名两套（`create_at` vs `created_at`）必须先定死，否则第 6 天建的新表继续错下去；③ `023` 的工时在计划里写 1.5 小时、任务文档里写 2 小时，第 6 天总工时对不上。

### B1. `028-nav-history-csv-import-api.md` — 把 `create_fund` 当 pytest fixture 用，这个 fixture 不存在

- **具体位置**：步骤 5 和步骤 6 的测试签名 `def test_import_nav_history_csv_success(client, create_fund)`、`def test_import_nav_history_csv_rejects_invalid_row(client, create_fund)`。
- **为什么做错**：`conftest.py`（任务 015 产出）里只有 `prepare_test_database`、`app`、`client`、`clean_db` 四个 fixture，没有任何 `create_fund`。`factories.py`（任务 016 产出）里的 `create_fund` 是**普通函数**，不是 fixture，不会自动注入。新手照抄这两个签名，运行必报 `fixture 'create_fund' not found`，而且两条测试是 error 不是 failed，新手会以为是环境坏了，排查方向完全跑偏。同文件的 `test_import_nav_history_csv_rejects_unknown_fund_code(client)` 又没带这个参数——同一份文档里两种写法，说明是笔误不是设计。
- **改成什么**：两个测试签名改成 `(client)`，函数体第一行改成调用工厂函数。并在文件顶部加一行 `from factories import create_fund`，与 022 保持一致。同时在该文件「新概念」一节补一句说明：`factories.py` 里的函数是普通 Python 函数，不是 pytest fixture，必须显式 `import` 后调用，不能写进测试参数列表。

### B2. `032-position-snapshot-tests.md` — 重复定义工厂函数，与 016/017 的完成标准直接冲突

- **具体位置**：步骤 1 在 `test_position_snapshots.py` 里重新定义了 `create_blogger()`、`create_fund()`、`create_initial_position()`、`create_operation()` 四个函数。

- **改成什么**：032 步骤 1 整段替换成两步：① 把 `create_initial_position()` 和 `create_operation()` **追加进 `backend/tests/factories.py`**（`create_operation` 的签名要能支持 `shares=None` 表示不传该字段，直接把 032 里写的那个版本搬过去即可）；② 在 `test_position_snapshots.py` 顶部写 `from factories import create_blogger, create_fund, create_initial_position, create_operation`。同任务的完成标准里加一条：`grep -rn "def create_blogger\|def create_fund\|def create_initial_position\|def create_operation" tests/` 结果全部来自 `factories.py`。

### B3. `040-delivery-check-and-doc-sync.md` — 验收一个没有任何任务实现的接口

- **具体位置**：步骤 5 的 `curl -i "http://127.0.0.1:5000/api/v1/nav-history"`；验收清单第 299 行 `GET /api/v1/nav-history 可用`；验证方式第 417 行同样列了这个接口。

### B4. `033`–`039`（第 8、9 天七个接口任务）— 完全没有自动化测试

- **具体问题**：033/034/035/036/037/038/039 七份文档的「完成标准」最后一条都是"`pytest -q` 全部通过"，但没有一份要求新增测试文件或测试函数。全项目最后一份新增测试的任务是 032。
- **为什么做错**：跑全量 `pytest -q` 通过只能证明"没改坏旧的"，证明不了"新写的对"。这七个接口承载了整套系统最脆的逻辑：成本 ≤ 0 返回 `null` 不返回 0、缺净值返回 `null` 不用最近净值兜底、超额卖出照实返回负数、038 那个只在"缺净值博主 id 更小"时才复现的 `TypeError`。这些规则现在只存在于 curl 手工验证里，改一行代码就静默失守，而且没人会发现。
- **改成什么**：在第 8、9 天各补一个测试任务，编号 `036A`（收益模块测试，2 小时）和 `039A`（看板模块测试，2 小时），不要塞进 036/039 本身——那两个任务已经标了 2 小时，再加测试就超 2 小时上限，必须拆。测试清单至少覆盖：

  - 缺净值 → 基金级 `null`、博主级 `null`、全局级 `null`（三层各一条）
  - 博主无持仓 → 返回 `0` 不是 `null`
  - 038 的"同一只基金、缺净值的博主 id 更小"场景必须返回 200 不是 500
  - `039` 空范围时 `summary` 的 `*_shares`/`*_amount` 带小数位不是裸整数 `0`
  - 每个看板接口的非法 `return_date` 返回 400

### B5. 全部 40 份 — CORS 没有任何任务

- **具体问题**：40 份任务文档、4 份计划文档里，"CORS""跨域""`Access-Control`""`flask-cors`"零出现（已全文检索确认）。
- **为什么做错**：前端 `frontend/` 跑在 `localhost:5173`，后端跑在 `127.0.0.1:5000`，是标准跨源。没有 CORS，浏览器预检请求直接被拦，所有接口在联调时全部失败。新手不会往跨域上想，会一路排查接口代码、数据库连接，浪费半天到一天。这不是"以后再说"的工程优化，是联调的第一道门。
- **改成什么**：新增任务 `041`，放在第 10 天第一个，1.5 小时。内容：`pip install flask-cors` 并写进 `backend/requirements.txt`；在 `app/__init__.py` 的 `create_app()` 里注册 `CORS(app, resources={r"/api/*": {...}})`；新概念说明要解释 Origin（源）、preflight（预检请求，OPTIONS）、`flask-cors` 是 Flask 的跨域扩展这三件事；验证方式用 `curl -i -X OPTIONS -H "Origin: http://localhost:5173" -H "Access-Control-Request-Method: POST" http://127.0.0.1:5000/api/v1/operations`，预期响应头带 `Access-Control-Allow-Origin`。配置参数照 `api-contract-gaps.md` 5.1 的 1.13。

### B6. 全部 40 份 — 全局错误处理器没有任何任务

- **具体问题**：40 份任务文档里没有一份要求注册 `@app.errorhandler`。backlog 里记的是 P1「功能闭环后」，但"功能闭环"就是 040，之后没有任务了。
- **为什么做错**：Flask 默认对 404 路径、405 方法、非法 JSON、未捕获异常返回 **HTML 错误页**。前端 axios 拿到 HTML 字符串，`response.json()` 直接抛。022 步骤 1 已经预演过这个问题——它写"预期失败。可能是 HTTP 500，也可能是 Flask 直接抛出异常栈，取决于任务 010 的错误处理怎么写的"，这句话本身就说明作者知道这里没有兜底。038 常见坑 1 描述的那个 `TypeError` 也是同样结局：接口返回 500 HTML。
- **改成什么**：与 B5 合并成任务 `041`（CORS + 全局错误处理器共 2.5 小时，拆成 `041` 和 `042` 也可以）。错误码和 HTTP 映射照 `api-contract-gaps.md` 5.1 的 1.8、1.9：`INVALID_JSON`/400、`ENDPOINT_NOT_FOUND`/404、`METHOD_NOT_ALLOWED`/405、`INTERNAL_ERROR`/500，`details` 固定 `[]`。必须在 `create_app()` 里注册，且要说明"为什么不能只在某个 Blueprint 里注册"。

- **具体位置**：

  - 任务 `007` 文档里的建表 SQL、任务 `008` 的排序白名单（`"created_at": "b.created_at"`）、任务 `016` 常见坑 2：用的全是 `created_at` / `updated_at`。

## 三、口径不一致问题

### C1. `round(float(value), places)` 与"一律 Decimal、ROUND_HALF_UP"冲突

- 涉及文件：`031`、`034`、`036`、`037`、`038`、`039` 六份，都定义了同一个 `_to_number()`：`return round(float(value), places)`。
- 冲突点：`api-contract-gaps.md` 5.1 的 1.11 要求"一律 `Decimal` 不用 `float`""四舍五入模式统一 `ROUND_HALF_UP`"。而 Python 的 `round(float, n)` 走的是 **ROUND_HALF_EVEN**（银行家舍入），`round(0.5)` 得 `0` 不是 `1`。六份任务文档把金额先转成 `float` 再舍入，精度口径和舍入口径两条都偏了。
- 改法：把 `_to_number()` 统一改成 `Decimal.quantize(Decimal("1.0000"), rounding=ROUND_HALF_UP)` 再转 `float` 输出，并在 `029` 或 `031` 首次引入时作为新概念讲清楚 `quantize()` 和 `ROUND_HALF_UP`。**不要**让六份文档各改各的——在 `031` 里定一个标准实现，其余五份照抄同一段。

### C2. `023` 工时：计划 1.5 小时 vs 任务文档 2 小时

- `plans/README.md` 第 23 行和 `plans/backend-day5-to-day9-40h-plan.md` 第 125 行都写"023 统一分页与排序校验工具 1.5 小时"，任务文档第 5 行写"约 2 小时"。
- 连带的：第 6 天"合计 8 小时"实际是 8.5 小时。
- 改法：以任务文档的 2 小时为准（023 的估算依据写得比计划表更具体，且 B9 修完会更重），把两份计划文档的第 6 天合计改成 8.5 小时，并在计划里注明"第 6 天超 0.5 小时，从 `024` 的 1 小时里挤不出来，接受这个溢出"。

### C3. 执行目录两套写法：`/mnt/d/...` 与 `/d/...`

- `019`–`028`、`033`–`040` 写 `cd /mnt/d/people/find_gold/backend`；`029`、`030`、`031`、`032` 写 `cd /d/people/find_gold/backend`。
- 前者是 WSL 路径，后者是 Git Bash / MSYS 路径。同一台 Windows 机器上只有一个能生效。新手做到第 7 天，`cd /d/...` 会失败，他会以为是自己的目录建错了。

### C4. `039` 的前置条件漏了 `038`

## 五、缺失任务

> 判断标准：**不做这件事，第 5–9 天的目标就达不成，或者交付物不可用**。

### M1. CORS 配置 — 必须有

前后端分离项目的第一道门。前端 `localhost:5173`，后端 `127.0.0.1:5000`，无 CORS 则浏览器拦截全部请求。许清楚已在 `api-contract-gaps.md` 2.3 和 5.1-1.13 定好口径（允许来源、方法、请求头、不发送凭据），但 001–040 没有任何任务去实现它。**口径写进接口文档不等于会被实现**——新手只照任务文档做事。归到 B5，编号 `041`。

### M2. 全局错误处理器 — 必须有

Flask 默认对 404 路径 / 405 方法 / 非法 JSON / 未捕获异常返回 HTML 错误页，前端解析崩溃。022 步骤 1 和 038 常见坑 1 都已经在文档里预演过这个失败形态，但两处都只是"描述现象"，没有人负责修。归到 B6，与 M1 合并为 `041`。

### M3. 净值列表查询接口 `GET /api/v1/nav-history` — 必须有

`040` 的验收清单要求它可用（见 B3）。没有它，CSV 导入 1000 行后无法核对、无法展示，录错了也无法发现（净值没有编辑和删除接口）。接口定义草稿已在 `api-contract-gaps.md` 5.3 写全，直接落地即可。编号 `026A`。

### M4. 第 8、9 天接口测试 — 必须有

033–039 七个接口零测试覆盖。详见 B4。编号 `036A`、`039A`。

### M5. 演示数据 / seed 脚本 — 必须有

- 现状：`034`、`035`、`036`、`037`、`038`、`040` 六份文档的验证命令都依赖"数据库里存在真实的博主和基金"，每份都得写一句"把 `1` 和 `101` 换成实际存在的 ID"。`040` 步骤 4 甚至直接写了"如果数据库里没有……请换成实际存在的 ID，或者只记录『前置数据不足』"。

### 关于 backlog 里"金额与份额统一用 `Decimal`"这条 P1 的判断

backlog 里写着"**第 8 天做收益计算前必须完成，否则收益数字不可信**"，但 001–040 里没有对应任务。核对后的结论是：**这条的实际风险已经被覆盖了，不需要单独补任务，但 backlog 的措辞必须改。**

判据：`020` 用 `float()` 只发生在两处——解析入参和响应序列化；数据库存的是 `DECIMAL(18,4)`；`030` 从库里读出来是 `Decimal` 并全程 `Decimal` 计算；`033` 也是全程 `Decimal`。累加链路上没有任何一环经过 `float`。所以"几十笔累加对不上账"这个风险在当前实现下不成立。

建议动作：把 backlog 该条的"适合阶段"从"第 8 天做收益计算前必须完成"改成"**已由 030/033 的 Decimal 化覆盖，降级 P3：仅清理 020 接口层的 `float()` 转换**"，并在 `040` 的验收清单里加一条检查项："确认 operations 的金额从入参到落库到累加全程没有经过 `float`"。这样既不留悬案，也不会让新手去做一件没有收益的事。

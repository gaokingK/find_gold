## 新概念：净值

净值的英文是 Net Asset Value，通常缩写为 NAV。

在本项目里，净值表示某只基金在某一天的单位净值。  
例如：

```text
基金代码 000001，日期 2026-09-30，净值 1.2345
```

注意：本项目的净值表只保存「某只基金某一天」的净值，不保存博主信息。  
博主持仓是通过 `initial_positions` 和 `operations` 计算出来的，再根据基金和日期去查净值。

## 具体步骤

### 步骤 1：确认净值的主视角

**必要性：**  
净值属于基金，不属于博主。同一只基金对不同博主来说是同一个净值。

确认关系：

```text
nav_history.fund_id -> funds.id
```

不要在 `nav_history` 表里加 `blogger_id`。  
如果加了，同一个基金同一天就要为每个博主重复保存一份净值，数据冗余且容易不一致。

---

### 步骤 2：确认字段定义

**必要性：**  
字段定义决定建表 SQL、接口参数和 CSV 列名。先确认字段，再写代码。

表名：

```text
nav_history
```

字段定义：

| 字段 | 类型 | 是否必填 | 示例值 | 说明 |
| --- | --- | --- | --- | --- |
| id | INT AUTO_INCREMENT | 是 | `1` | 主键，后端生成 |
| fund_id | INT | 是 | `1` | 关联 `funds.id` |
| nav_date | DATE | 是 | `2026-09-30` | 净值日期，格式 `YYYY-MM-DD` |
| nav | DECIMAL(18, 4) | 是 | `1.2345` | 单位净值，必须大于 0 |
| created_at | DATETIME | 是 | `2026-09-30 10:00:00` | 创建时间 |
| updated_at | DATETIME | 是 | `2026-09-30 10:00:00` | 更新时间 |

---

### 步骤 3：确认唯一约束

**必要性：**  
同一只基金同一天只能有一个净值。否则第 8 天计算市值时不知道应该取哪一个。

唯一索引：

```text
uk_nav_history_fund_date (fund_id, nav_date)
```

它表示：

```text
fund_id + nav_date 唯一
```

---

### 步骤 4：确认外键和索引

**必要性：**  
外键保证净值必须挂在真实基金上，索引影响按日期和基金查询的速度。

外键：

| 外键 | 指向 | 说明 |
| --- | --- | --- |
| `fk_nav_history_fund` | `funds(id)` | 基金必须存在 |

索引：

| 索引 | 字段 | 作用 |
| --- | --- | --- |
| `uk_nav_history_fund_date` | `fund_id, nav_date` | 唯一约束，也支持按基金和日期查询 |
| `idx_nav_history_date` | `nav_date` | 支持按日期查询 |

---

### 步骤 5：确认重复提交行为

**必要性：**  
用户可能录错净值，也可能同一天重复提交。第一版没有编辑和删除接口，所以需要提前决定重复提交怎么处理。

本设计选择：

```text
同一 fund_id + nav_date 再次提交时，更新已有净值。
```

理由：

1. 第一版没有净值编辑和删除接口。
2. 用户录错后需要一种简单的修正方式。
3. 语义清晰：某天净值以最后一次提交为准。

注意：  
这仍然满足「同一基金同一天只允许一条净值」，因为不是新增第二条，而是更新第一条。

---

### 步骤 6：确认 CSV 导入策略

**必要性：**  
CSV 导入可能几十行、几百行。如果部分成功，用户很难知道哪些行进了库、哪些行失败了。

本设计选择：

```text
全部成功才入库。
```

也就是说：

1. 先解析整个 CSV。
2. 再校验所有行。
3. 只要有一行错误，就不写数据库。
4. 所有错误一起返回给前端。

理由：

1. 第一版实现简单。
2. 不会出现「导入了一半」的中间状态。
3. 用户可以根据完整错误列表修正文件后重新导入。

---

### 步骤 7：确认 CSV 列名

**必要性：**  
CSV 列名是前后端和文件模板的共同约定，不能随便改。

第一版 CSV 使用以下列名：

```text
fund_code,nav_date,nav
```

示例：

```csv
fund_code,nav_date,nav
000001,2026-09-30,1.2345
000002,2026-09-30,2.3456
```

说明：

- CSV 使用 `fund_code`，不使用 `fund_id`，因为使用者更容易识别基金代码。
- 后端导入时会根据 `fund_code` 查找对应的 `fund_id`。
- 如果 `fund_code` 不存在，导入失败，不写库。

## 常见坑

### 1. 在净值表里保存博主 ID

净值属于基金，不属于博主。  
不要把 `blogger_id` 放进 `nav_history`。

### 2. 使用 FLOAT 保存净值

不要使用：

```sql
FLOAT
DOUBLE
```

净值必须使用：

```sql
DECIMAL(18, 4)
```

否则后续计算市值和收益率会出现精度问题。

### 3. 允许同一基金同一天多条净值

不要漏掉唯一索引：

```sql
UNIQUE INDEX uk_nav_history_fund_date (fund_id, nav_date)
```

否则后续计算市值时会出现歧义。

### 4. CSV 导入一半成功一半失败

第一版不要做部分成功。  
必须先解析和校验所有行，有一行错误就不写库。

### 5. 忘记说明重复提交行为

如果设计文档没写清楚重复提交怎么处理，后续接口实现就会猜。  
本设计明确：同一天重复提交时更新旧值。

### 6. 把设计文档放到 `backend/docs/`

净值表设计是项目级文档，应放在：

```text
docs/backend/design/
```

不是：

```text
backend/docs/
```

## 这个文件的作用

`docs/backend/plans/` 下有多份计划文档，每份覆盖一段时间。如果每份都写一句「当前应执行任务 XXX」，改进度时就要同时改好几处，漏改一处就会有人照着过期的指示去做已经完成的任务。

所以规则是：

1. **「当前任务」只在这个文件里写一处。** 其他计划文档只列出自己那段时间包含哪些任务，不写当前进度。
2. 每验收通过一个任务，只改这个文件。
3. 找不准该做什么时，看这个文件，不要看别的计划文档。

## 全局约定

这几条适用于所有任务：

1. **成功响应统一返回 HTTP `200`**，新增接口也不返回 `201`。`success()` 函数没有 `http_status` 参数，传了会报 `TypeError`。
2. **API 路径统一加 `/api/v1/` 前缀。**
3. **测试只允许连接 `fund_test_db`。** 测试夹具会执行 `TRUNCATE`，一旦连到开发库 `fund_db`，开发数据会被清空。出现任何指向 `fund_db` 的迹象就立即停止测试。
4. **数据库密码只通过环境变量传入**，不要写进任何会提交到 Git 的文件。
5. **列表接口的排序字段必须走白名单**，`page_size` 上限 `100`。排序字段是拼进 SQL 的，去掉白名单就是 SQL 注入。
6. **金额和份额在数据库里用 `DECIMAL`**，不用 `FLOAT`。

## 验收节奏

每完成一个任务，反馈：

1. 修改或新增的文件列表。
2. 验证命令和输出。
3. `pytest -q` 的完整输出（从任务 014 起每个任务都要跑，贴原文，不要只写「都通过了」）。
4. 响应字段是否和接口文档一致。
5. 有没有发现接口文档说不通的地方。
6. 遇到的问题。
7. 是否有未完成项。

上一个任务没验收通过，不要开始下一个。

## 这个文件的作用

`docs/backend/plans/` 下有多份计划文档，每份覆盖一段时间。如果每份都写一句「当前应执行任务 XXX」，改进度时就要同时改好几处，漏改一处就会有人照着过期的指示去做已经完成的任务。

所以规则是：

1. **「当前任务」只在这个文件里写一处。** 其他计划文档只列出自己那段时间包含哪些任务，不写当前进度。
2. 每验收通过一个任务，只改这个文件。
3. 找不准该做什么时，看这个文件，不要看别的计划文档。

**每一份为什么必须有**：

- `041`：前后端分离必备。前端 5173、后端 5000，不配跨域浏览器拦掉所有请求，而且报错看起来像接口写错，极难排查。
- `042`：不配的话 404/405/非法 JSON/500 返回的是 HTML，前端 axios 直接崩。
- `043`：022、028、032 三份文档里工厂函数有三种互斥写法，其中 028 照抄必然报 `fixture 'create_fund' not found`，而且报的是 error 不是 failed，新手会往环境方向排查。

- `046` / `047`：033–036 四个接口**零回归保护**，而这正是系统里数字最密集的部分——成本 ≤0 返回 null、缺净值返回 null、超额卖出照实返回负数，现在全靠手工 curl。
- `048` / `049`：037–039 三个接口**零回归保护**，与上面同理。

**顺序约束**：

1. `041` → `042`：042 的验证依赖 041 配好后接口能被正常请求。
2. `043` 必须早于 `044`、`046`、`047`、`048`、`049`：先统一工厂函数，再写新测试，否则新测试又引入第四种写法。
3. `044` 必须早于 `046`：`create_nav_history` 这个工厂函数由 044 步骤 7 产出，046 步骤 2 直接导入它——顺序反了第一步就报 `ImportError`，而且是 error 不是 failed，新手会往环境方向排查。
4. `046` → `047`：先测 Service 层纯函数，再测 HTTP 接口。函数算错了接口一定错，反过来不一定，先做前者能更快定位问题。
5. **`045` 与 `046`–`049` 之间没有依赖**。四份测试任务全部用工厂函数在测试库 `fund_test_db` 自造数据，与 seed 零依赖；045 的真实下游是 `034`–`038`、`040` 的手工验证和固定 ID 替换。不要把 045 当成测试任务的硬前置。

**编号规则**：补发批次统一用连续数字 `041` 起，不用字母后缀。原因是字母后缀（`026A` 这种）表达的是「插在 026 之后执行」，而这一批是独立批次，插号会让人误以为要回到主线中间去做。

## 全局约定

这几条适用于所有任务：

1. **成功响应统一返回 HTTP `200`**，新增接口也不返回 `201`。`success()` 函数没有 `http_status` 参数，传了会报 `TypeError`。
2. **API 路径统一加 `/api/v1/` 前缀。**
3. **测试只允许连接 `fund_test_db`。** 测试夹具会执行 `TRUNCATE`，一旦连到开发库 `fund_db`，开发数据会被清空。出现任何指向 `fund_db` 的迹象就立即停止测试。
4. **数据库密码只通过环境变量传入**，不要写进任何会提交到 Git 的文件。
5. **列表接口的排序字段必须走白名单**，`page_size` 上限 `100`。排序字段是拼进 SQL 的，去掉白名单就是 SQL 注入。
6. **金额和份额在数据库里用 `DECIMAL`**，不用 `FLOAT`。

## 二、补发批次执行顺序（共 16 小时）

主线任务做到哪就算哪，补发批次随时可穿插；但**补发批次内部必须按下面顺序**。

```text
第 1 步  041  配置 CORS 跨域              1.5h ─┐
第 2 步  042  注册全局错误处理器            1.5h ─┤ 地基，最先做
                                            ─┘
第 3 步  043  统一测试工厂函数              1.5h ─┐
第 4 步  044  净值列表查询接口              2h   ─┤ 测试前置
第 5 步  046  收益 Service 层单元测试        2h   ─┤
第 6 步  047  收益接口测试                  2h   ─┤
第 7 步  048  看板 null 三层污染测试         2h   ─┤
第 8 步  049  近期操作统计接口测试           2h   ─┘
第 9 步  045  seed 数据脚本                 2h   ← 与 046–049 无依赖，随时可做；
                                                   真实下游是 034–040 的手工验证
```

### 为什么是这个顺序

| 约束 | 原因 |
| --- | --- |
| 041 → 042 | 042 的验证依赖 041 配好后接口能被正常请求 |
| 043 先于 044/046–049 | 先统一工厂函数，否则新测试引入第四种写法 |
| **044 先于 046** | `create_nav_history` 由 044 步骤 7 产出，046 直接导入。顺序反了第一步报 `ImportError`（error 不是 failed，会误导排查方向） |
| 046 → 047 | 先测 Service 层纯函数再测接口。函数算错了接口一定错，反之不成立 |
| 045 与 046–049 **无依赖** | 测试任务全用工厂函数在测试库自造数据；045 服务于 034–040 的手工验证与固定 ID 替换 |

### 执行细节提醒

- **041 / 042 是增量修改** `app/__init__.py`，不是整文件替换。改完跑 `git diff app/__init__.py`，只允许有 `+` 行。
- **042 最关键的坑**：`run.py` 开着 `debug=True`，必须显式加 `app.config["PROPAGATE_EXCEPTIONS"] = False`，否则 500 处理器一次都不会被调用。
- **046–049 测试只连 `fund_test_db`**（夹具会 TRUNCATE），连到 `fund_db` 会清空开发数据。
- 048 若测出 038 已知的「缺净值博主 id 更小时 500」bug，**测试变红是预期结果**——只反馈，不要在本任务里改业务代码。
- 045 的 `status` 会随时间自然变化（派生字段按当天日期实时算），这是设计使然不是 bug。验证 `status` 时先算当天应有值再比对，**不要**用 `date.today()` 去修 seed。
